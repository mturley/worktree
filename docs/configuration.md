# Configuration

← [Back to the README](../README.md) · [CLI reference](cli.md) · [Setup guide](setup.md)

You rarely need to edit config files by hand. `worktree setup` writes them, and the web UI's **Settings** window edits every key described here. Its tabs are General, Connected Services (GitHub, Jira, Slack), Notifications, UI Access and Devices, plus a Logs tab showing the background polling.

worktree reads three files:

| File | Holds |
|---|---|
| `~/.config/worktree/config.yaml` | worktree's own settings |
| `~/.config/watcher/auth.yaml` | GitHub, Jira and Slack credentials (mode `0600`), shared with other tools built on the [watcher](https://github.com/mturley/watcher) library |
| `~/.config/watcher/config.yaml` | Non-secret Jira behavior, such as bot usernames and custom fields |

## `~/.config/worktree/config.yaml`

```yaml
# Where new worktrees are created
worktrees_base: ~/.worktrees

# Editor for `worktree open` and the UI's "Open in editor" (e.g. code, cursor, zed)
editor: code

jira:
  # Project keys used to spot issue keys in branch names and PR titles
  projects: [PROJ, OTHER]
  # Extra hosts whose /browse/KEY links are Jira issues, e.g. an old address
  # that now redirects to your atlassian.net site
  alias_hosts: [issues.your-org.com]

# Turn a service off entirely: it's never contacted and its credentials are never read.
# Absent means on.
watchers:
  github: true
  jira: true
  slack: true

notifications:
  disabled: false          # Turn every notification off (per-worktree choices are kept)
  command_enabled: false   # Also run a shell command for each notification
  # Runs under sh -c with $event, $resource, $description, $worktree and $cmuxtitle set
  command: 'notify-send "$event" "$description"'

git:
  background_fetch: true   # Fetch each repo in the background for the Code tab's ahead/behind
  fetch_interval: 3m       # Minimum 1m

ui:
  password: ...                  # Required; generated by `worktree setup`
  https_port: 8476               # HTTPS port for other devices
  allowed_hosts: [my-mac.local, 192.168.1.20]   # Names/IPs other devices use; also the certificate's names
  tls:
    cert_file: ...
    key_file: ...
  remote_access_disabled: false  # Keep the certificate, but don't serve HTTPS
  cmux_features_disabled: false  # Ignore cmux even when it's available
  port_scan_disabled: false      # Don't scan for the ports each worktree is listening on
```

`editor` is the only way to choose the editor for the web UI. The CLI's `worktree open` falls back to `$EDITOR` when it isn't set, but the UI server has no terminal for a terminal editor to run in.

## `~/.config/watcher/auth.yaml`

```yaml
services:
  github:
    token: ghp_...
  jira:
    host: your-org.atlassian.net
    email: you@example.com
    token: ...
  slack:
    token: xoxc-...
    cookie: xoxd-...
    workspace_domain: your-workspace
```

Setup writes and tests this file. See [Connecting services](setup.md#connecting-services) for how to get each credential.

## `~/.config/watcher/config.yaml`

```yaml
jira:
  bot_usernames: [automation-bot]   # Jira users whose comments and changes are attributed to a bot
  custom_fields:                    # Friendly name → Jira custom field ID, fetched and cached for each issue
    epic_key: customfield_10014
```

## Environment variables

| Variable | Overrides |
|---|---|
| `WORKTREES_BASE` | `worktrees_base` |
| `WORKTREE_DB` | The database path (default `${XDG_DATA_HOME:-~/.local/share}/worktree/worktree.db`) |
| `XDG_CONFIG_HOME` | Where `worktree/config.yaml` is looked for (default `~/.config`) |
